# AGENTS.md

Tauri 2 desktop app: React 19 + TypeScript, Vite, Tailwind v4, shadcn/ui (Base UI, `base-nova`),
TanStack Router (file-based, `src/routes`) + Query + Devtools, Vitest, oxlint, oxfmt.
Rust backend lives in `src-tauri/`. The website (download/marketing page, GitHub Pages) is a separate
Astro package in `site/` with its own lockfile: `cd site && pnpm install && pnpm dev`.

`pnpm demo` runs the app in a browser on made-up data (`src/lib/demo/`, Tauri IPC mocked, no
account or Rust). `pnpm screenshots [name…]` retakes `docs/screenshots/` from it (shots in
`scripts/demo-shots/`). Update the demo fixtures when a page needs new endpoints.

Read `DESIGN.md` before any UI work: colors, type, spacing and layout rules live there.

## Environment

All tooling comes from `flake.nix` (loaded by direnv via `.envrc`). If direnv is not active in
your shell, prefix commands with `nix develop -c`.

## Commands

- `pnpm check` — oxfmt --check, oxlint, tsc, vitest run. Run before finishing any change.
- `pnpm fmt` — format TS/JSON/CSS with oxfmt (never prettier).
- `pnpm build` — typecheck + vite build.
- `cd src-tauri && cargo fmt && cargo clippy` — Rust checks.
- `pnpm dlx shadcn@latest add <component>` — add shadcn components into `src/components/ui`.
- `src/routeTree.gen.ts` is generated by the router Vite plugin; don't edit it.

## Commits and changelog

Commit subjects are the changelog: `git-cliff` (`cliff.toml`) turns them into `CHANGELOG.md`
and each GitHub release's notes, which the in-app updater shows too.

- Conventional Commits: `type(scope): subject`. `feat`, `fix` and `perf` reach the changelog;
  `chore`, `ci`, `docs`, `refactor`, `style`, `test` and `build` don't. `feat!:` marks a
  breaking change.
- Scope is the user-facing area: `analysis`, `portfolio`, `markets`, `assistant`, `alerts`…
- Write the subject for a user, not a reviewer: what they can now do or what got better.
  `feat(analysis): trading profile finds habits in your buy and sell history`, not
  `feat: add profileTrades and FindingDetail`.
- One user-facing change per `feat`/`fix` commit. Follow-up polish to an unreleased feature
  is `refactor`/`style`, or squash it in, so the changelog gets one line per feature.
- PRs are squash-merged and the PR title becomes the commit on main, so the PR title follows
  the same rules (CI checks it: lowercase after the colon, no final period).
- `just changelog` previews the next release's notes; `just release 1.2.3` writes
  `CHANGELOG.md` into the release commit.

## React components

- One component per file, kebab-case file name: `HomePage` lives in `home-page.tsx`.
- Put a component under the module it belongs to: `src/components/<module>/<component>.tsx`.
  Nest deeper when a module grows: `src/components/<module>/<submodule>/<component>.tsx`.
- Components shared across modules go in a generic module named for their purpose,
  e.g. `src/components/layout/`, `src/components/common/`.
- `src/components/ui/` holds only base UI primitives (shadcn components). Don't put feature
  components there; compose them from `ui` in a module folder.
- Route files in `src/routes/` (including `__root.tsx`) hold only the most basic structure:
  route definition, data loading (`loader`, `beforeLoad`, search/param validation) and rendering
  module components. No `useEffect`, state, event handlers or other component logic; move that
  into a component under `src/components/<module>/`.

## String codes

- Avanza's codes live as named constants in `src/lib/avanza/codes.ts` (`InstrumentType`,
  `TransactionSide`, `OrderSide`). Compare against those, not raw strings:
  `h.type === InstrumentType.Fund`, not `h.type === "FUND"`. Add new codes there.
- Use `as const` objects with a same-named union type, not TS `enum`s.

## Running the app (agents)

`pnpm tauri dev` never exits on its own and spawns children (vite on :1420, the app binary).
`timeout` or killing a process group leaves orphans (tauri puts the app binary in its own process
group). Always use the script, which runs it in its own session and kills the whole session:

```sh
scripts/tauri-smoke.sh 5 /tmp/tauri.log   # seconds the app stays up after it starts, log path
```

The script uses its own vite port (first free from 1430), so it runs fine next to the user's debug
session on :1420. It shares the normal debug build in `src-tauri/target`. Never set
`CARGO_TARGET_DIR` to a path inside `src-tauri/`: tauri dev watches it and rebuild-loops.
It waits at most 60s for the app to start (warm build: ~5s). After a cold build or a
`cargo clean`, build first with `cd src-tauri && cargo build`, or set `START_TIMEOUT=600`.
Never kill processes you did not start. The first run compiles from scratch (a few minutes).
